## 2026-11-12 현재 상태 갱신

신규 전투는 규칙4이며 일반 전술 카드·재추첨과 불씨 원정4전장·야영지 선택·온기 이월·전투 저장을 구현했다. 가로 화면 전용으로 결정했고 세로 지도 확대는 폐기했다. 원정의 준비 선택이 배치 판단을 바꾸는 정도는 부족하다는 Claude41차 검수가 있다. 다음은 행동형 준비·갈림길의 설계와 사람 플레이 확인이다. 수치 조정이나 후속 기능을 완료한 것으로 취급하지 않는다. 최신 검증과 인계는 STATUS/CODEX-HANDOFF를 따른다. 아래는 작성 당시의 기록이다.

## 2026-11-09 현재 방향 — Terra 구현 인계

현재 신규 전투는 규칙 3으로 성문 14, 숲길·바위 고개·습지 각 12웨이브다. 아래 11-06 기록의 “미적용”은 당시 상태이며 현재 구현 상태를 뜻하지 않는다. 일반 전투 카드·다시 뽑기는 아직 구현되지 않았다.

사용자의 “짧고 쉽고 강화·전략이 부족하다”는 피드백을 바탕으로 [Astra 게임 방향서](ASTRA-GAME-DIRECTION-2026-11-09.md)와 [Terra 구현 계획](TERRA-IMPLEMENTATION-PLAN.md)을 작성했다. 다음 순서는 일반 3·6·9웨이브 전술 선택과 재추첨을 화면·저장까지 완성하고, 같은 후보에서 병과 역할·상성 및 후반 압박을 비교하는 것이다. 기존 캐릭터를 유지하며 새 맵·Lv4는 이 한 판의 평가 뒤 검토한다.

핵심 호환 조건은 v0~3 보존, 다음 공개 규칙 v4, 일반/증원 모드와 카드 상태의 분리다. 초기 후보 수치와 사람 평가가 필요한 부분은 위 문서에 구분했다. 이번에는 설계 문서만 작성했으며 새 게임 규칙을 적용하지 않았다.

## 2026-11-06 전투 길이·난도 격리 후보 비교

- 사용자 피드백에 따라 기존 규칙(0~2 난도, 3전장, 9개 자동 편성, 잔불 사용 여부, 4시드) 648판에 전투 시간·최종 2/3레벨 병력 수를 추가 기록했다. 기본 난도 바위 고개는 72/72 승리, 승리 게임시간 중앙값 281.5초였다. `Docs/r24-gameplay-baseline.csv`.
- 규칙을 실제 게임에 적용하지 않고 기본 난도 적 수를 125·150·175%로 바꾸고 간격을 비례 축소한 648판은 `Docs/r24-density-candidates.csv`. 바위 고개 승리 72·64·56/72, 승리 게임시간 중앙값 285.7·296.0·291.6초였다. 적 수 증가는 압박은 주지만 길이를 크게 늘리지 않았다.
- 기존 마지막 4개 웨이브를 복제해 4웨이브를 덧붙인 탐색 후보 648판은 `Docs/r24-extended-candidates.csv`. 바위 고개 기존 밀도에서는 72/72 승리, 중앙값 435.2초, 125%에서는 68/72 승리, 447.4초였다. 단순 반복은 실제 새 콘텐츠나 최종 설계가 아니며 전략적 선택이 늘었다는 증거도 아니다.
- 재현: `GameplayDurationProbe.cs`의 인자 `난도 밀도 on 추가웨이브수`를 사용한다. 추가 웨이브 4개와 보스 배율 1.15는 탐색에서만 적용한다. 4시드와 고정 편성 자동 전략의 한계 때문에 이 수치만으로 재미·난도를 확정하거나 기존 기록을 덮지 않는다.
- 다음 구현은 기존 저장·기록에 영향을 주지 않는 별도 규칙 버전 또는 선택 모드를 기준으로, 적 조합 변주와 추가 강화/선택의 상호작용을 설계해야 한다. 아직 이 후보는 게임에 적용하지 않았다.

## 2026-11-06 실제 플레이 피드백과 다음 작업

- 사용자는 Windows 플레이 후 바위 고개 8/8 승리 화면(최대 적 62/100, 처치 212)을 보여주며 전투가 빨리 끝나고 쉽고, 강화하거나 전략적으로 선택할 요소가 부족하다고 평가했다. 우선순위 질문에는 **전투 길이·난도와 강화·전략을 함께 개선**한다고 답했다. 실제 플레이 시간과 난도 설정은 확인되지 않았다.
- 소리는 `소리 크게`였던 것으로 기억하지만 듣지 못했다고 밝혔다. 기존 장면에 오디오 리스너가 없는 것을 확인해 별도로 수정하고 실제 오디오 신호를 검사했다. 실제 Windows 청취 결과는 재확인해야 한다.
- 게임성 다음 단계: 기존 저장과 완료 기록을 보존할 규칙 버전을 먼저 정하고, 더 긴 전투와 추가 성장·선택이 결합된 후보를 만든다. 같은 전장·난도·시드와 편성으로 현재/후보의 전투 시간, 승패, 최대 적 수, 강화·분기 횟수를 비교하고, 특정 한 병과만 최선이 되지 않는지 확인한다. 자동 실험은 실제 재미와 난이도 평가를 대신하지 않는다.
- **아직 전투 길이·난도·강화 규칙을 변경하지 않았다.** 기존 저장 검증은 병력 1~3레벨과 기존 투자 비용을 전제로 하므로 추가 강화에는 저장 호환과 기록 분리가 필요하다.

## 목표

플레이어가 적을 막는 과정에서 병과와 위치를 고르고, 패배한 뒤에는 편성을 바꾸어 다시 시도할 이유를 알 수 있도록 한다. 적 100명 도달 시 패배하는 현재 규칙을 기준으로 한다.

## 작업 원칙

- 게임 규칙과 저장 호환을 확인하고, 기존 플레이 데이터 및 Windows 빌드 경로를 보존한다.
- 배치·강화·대상 우선순위의 결과를 화면에서 이해하기 쉽게 보여준다. 조언은 실제 상태에 근거하며 승리를 보장하는 것으로 표현하지 않는다.
- 수치 변경은 같은 전장·난도·시드에서 후보와 기존 결과를 비교하고, 사람의 플레이 체감을 확인한 뒤 결정한다. 자동 플레이는 재미나 난도 평가를 대신하지 않는다.
- 변경 후 관련 규칙 검사와 빌드를 수행하고, 실제 화면·기기에서 확인하지 못한 항목은 구분해 기록한다.

## 이번 작업: 패배 후 남은 적 안내

결과 카드에 골드와 빈 자리, 편성 안내를 표시한다. 적이 100명에 도달해 패배하면 살아 있는 적의 종류를 세어 가장 많은 종류와 숫자를 추가한다. 최다 수가 같으면 해당 적 이름을 최대 두 종류까지 보여주고 더 있으면 ‘등’을 표시하며, 전투를 포기한 경우에는 표시하지 않는다. 전투 계산이나 저장 형식은 바꾸지 않는다.

검증: 남은 적 수, 동률, 죽은 적 제외, 전투 포기와 빈 목록에 대한 독립 검사가 통과했다. Unity Mac 빌드와 앱 서명도 확인했다. 격리된 로컬 Web 시험 화면에서 320×300과 800×500 크기의 결과 카드 및 동률 표시를 확인했다. 실제 Mac·Windows 결과 화면과 터치 기기 조작은 별도 확인이 필요하다.

## 추가 작업: 복원 시점에 맞는 패배 안내

패배 순간의 자원과 웨이브 시작 시점의 자원은 다를 수 있다. 복원이 가능하면 결과 카드의 골드·빈 자리·추천을 실제로 복원할 웨이브 상태 기준으로 표시한다. 복원할 상태가 없으면 패배 시 골드로 구매를 권하지 않고 새 전투에서 편성을 바꾸도록 안내한다. 웨이브 복원과 준비 복원, 복원 없음에 대한 독립 검사가 통과했다. 격리 Web 시험에서 복원 전 안내와 복원 후 골드가 모두 54G인 것을 확인했다. Mac·Windows 실행판의 직접 조작은 별도 확인이 필요하다.

## 추가 작업: 전투 종료 후 웨이브 예고

패배 화면에 다음 웨이브·대장 예고가 남아 진행 가능한 것으로 오해할 수 있어, 승리와 패배 후에는 예고를 숨긴다. 준비·전투 중에는 기존 예고를 유지한다. 격리된 로컬 Web의 패배 시험 화면에서 수정 전 예고가 보이고 수정 후 사라진 것을 확인했다.

## 추가 작업: 남은 적에 맞는 힌트

100명 도달로 패배했을 때 한 종류가 가장 많이 남았다면 그 적의 특성에 맞는 짧은 편성 힌트를 표시한다. 힌트는 선택지 제안이며 패배 원인이나 승리 보장은 아니다. 최다 수가 같거나 전투 포기라면 특정 적을 지목하지 않고 복원 자원 기준 안내를 유지한다.

## 추가 작업: 기술자 지원 안내

기술자 배치 미리보기는 범위 안의 공격 병력 수를 보여준다. 여러 기술자의 공격 속도 지원은 더해지지 않고 가장 높은 값만 적용되므로 이 점을 미리보기와 도움말에 명시한다. 전투 수치와 기존 지원 계산은 변경하지 않는다. 겹친 지원이 더해지지 않고 가장 높은 값이 적용되는 독립 검사와 800×500 Web 화면의 배치·도움말 표시를 확인했다.

## 추가 작업: 패배 안내 검사 연결

기존 격리 화면 검사는 예전 별도 추천 함수를 확인하고 있어 결과 카드의 최신 추천과 달라질 여지가 있었다. 검사도 실제 결과 카드가 사용하는 추천 규칙을 호출하도록 연결했다. 격리 Web 시험에서 골드·레벨·빈 자리에 따른 여섯 결과를 확인했다.

## 추가 작업: 자동 전략의 동점 순서 고정

기존 Windows 기록과 Mac에서 같은 도전 모드의 216개 편성을 비교했을 때, 스마트 편성 28개의 최대 적 수가 달랐다. 승패는 모두 같았다. 스마트 편성은 길 사거리 점수가 같은 자리를 정렬할 때 순서를 정하지 않아 실행 환경에 따라 병과가 배치되는 순서가 달라질 수 있다. 동점인 경우 자리 번호순으로 정하도록 실험 도구를 수정했다. 이는 실제 게임 계산이나 기존 저장을 변경하지 않지만, 이전 자동 실험 결과와 새 결과를 직접 같은 기준으로 비교하면 안 된다. Mac에서 정렬 수정 전후 216판은 일치했다. Windows 재실행 비교는 아직 필요하며, 정렬 차이가 기존 플랫폼 간 차이의 원인이라는 점도 확정되지 않았다.

## 추가 회귀 확인

Mac에서 핵심 전투 검사 199건, 전투 저장·복원 및 손상 데이터 검사 6,282건과 웨이브 재시도 검사 2,799건을 통과했다. 마지막 웨이브 저장 상태의 1배·6배 결과 비교 36건도 통과했다. 격리 Web에서 800×500 첫 병력 배치, 전투 시작, 궁수 추가·강화를 확인했다. 320×300에서는 마우스 한 번으로 빈 자리에 배치되는 것을 확인하고, 도움말의 두 번 누르기 안내를 작은 터치 화면으로 한정했다. 터치 기기 실물에서는 확인하지 않았다. 자동 조작과 개발 시험 상태이며 실제 사람의 한 판 플레이 및 재미 평가는 아니다.

## 다음 우선순위

1. **병과·자리 선택 안내:** 적의 약점과 사거리, 빈 자리가 어떤 병과에 유리한지 전투 중 더 명확히 전달한다. 기존 추천을 먼저 실제 화면에서 확인하고 부족한 부분을 개선한다.
2. **패배 후 재도전:** 웨이브 복원 시 골드·편성이 시작 시점으로 돌아간다는 점이 충분히 명확한지 확인한다. 실제 복원 상태에 근거해 조언이 필요한지 검토한다.
3. **마지막 소탕:** 6배 소탕과 피해 없음 안내가 실제 플레이에서 적절한지, 사거리 밖 적을 찾기 쉬운지 확인한다.
4. **난도와 배지:** 임시 배지 기준과 병과 조합의 난도를 사람 플레이 및 여러 전략·시드로 재검토한다. 단일 자동 전략의 승패만으로 수치를 변경하지 않는다.
5. **손맛과 재도전:** 병과별 공격음, 경고·대장 처치의 체감과 전장 완료 후 동기를 점검한다. 추가 모드는 현재 한 판의 재미 검수 후 결정한다.
