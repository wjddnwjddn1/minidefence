# 잔불의 성채 · Codex와 Claude 협업

작성: 2026-11-09  
작성 시점 로컬 기준: `c846954` (`main`)  
목적: 기존 저장과 진행 중인 다른 작업을 보호하면서 일반 전투의 전술 선택을 구현하고 독립 검수한다.

## 함께 지킬 기준

- 사용자 지시가 이 문서와 기존 계획보다 우선이다. 시작할 때 각자 Git 브랜치, 원격 최신 커밋, 미커밋 변경과 최신 `Docs/CODEX-HANDOFF.md`, `Docs/CLAUDE-DIRECTION.md`, `Docs/CLAUDE-REVIEW.md`, `Docs/STATUS.md`를 확인한다. 이 문서의 커밋은 작성 시점 기준이며 현재 원격 상태를 뜻하지 않는다.
- [게임 방향서](ASTRA-GAME-DIRECTION-2026-11-09.md)와 [구현 계획](TERRA-IMPLEMENTATION-PLAN.md)을 순서대로 읽는다. 문서의 새 일반 카드·리롤·상성 수치는 아직 확정된 게임 기능이 아닌 후보이며, 구현과 검증 전 적용 완료라고 표시하지 않는다.
- 게임 계산·저장·표시·기록을 함께 추적한다. 기존 v0~3 저장 및 증원 동작과 기록은 보존한다. 일반 전투 카드 상태와 증원 모드의 의미를 분리하며, 미완성 규칙 4를 기본 새 전투에 켜지 않는다.
- 기존 Tiny Swords 캐릭터와 사용자 데이터를 보존한다. 별도 승인 없이 운영 웹판, 기존 배포 파일, 타인의 미커밋 작업을 덮거나 지우지 않는다.
- 재현하지 않은 테스트, 실제 기기 플레이·소리 청취, 배포·업로드를 완료한 것으로 보고하지 않는다. 실험용 데이터와 사용자 저장을 격리한다.

## 역할과 순서

1. **Codex — 구현 담당:** 구현 계획의 T0부터 시작한다. 최신 소스의 모드·드래프트·저장·기록 경로와 기존 검사를 먼저 추적하고, 버전 호환을 유지하는 작은 단위로 구현·검증한다. 일반 3·6·9웨이브 카드, 리롤 및 화면·저장은 계획 순서를 따른다. 각 완료 단위의 범위, 테스트, 남은 위험, 커밋을 인계에 적는다.
2. **Claude — 독립 검수 담당:** 먼저 읽기 전용으로 방향서와 현재 소스를 대조해 모드 분리·v0~3 저장·보상 중복·기록 귀속의 누락과 구현 순서 위험을 점검한다. 실제 수정은 Codex 담당 범위와 충돌하지 않는 별도 작업을 사용자와 정하거나 명확히 인계받은 경우에 진행한다. 검수 결과는 재현 조건, 근거 파일, 영향, 필요한 검증을 구분해 기록한다.
3. **통합:** 각자 작업 시작 전에 담당 범위·기준 커밋을 공유하고 같은 파일을 동시에 편집하지 않는다. 환경이 분리되어 있다면 각자 최신 원격을 확인하고 변경된 커밋을 전달한다. 같은 작업공간을 공유한다면 상대 작업 트리의 변경을 임의로 정리하지 않는다. 충돌이나 범위 변경 시 사용자와 서로에게 상태를 알린다.
4. **검수 후 반복:** Codex는 재현된 지적을 수정하고 필요한 회귀를 수행한다. Claude는 최종 변경과 실제 실행 증거를 다시 검토한다. 서로의 검수 결과와 자동 테스트만으로 게임의 재미를 확정하지 않는다.

## 첫 번째 검수 범위

- `Battle`에서 모드와 `Reinforcements` 존재가 각각 어떤 동작을 결정하는지, 저장·복원과 웨이브 재도전에서 어떤 정보가 유지되는지 추적한다.
- 일반 카드 도입 시 기존 증원 밀도·난도 제한·기록 및 보급과 얽힐 수 있는 지점을 파일·함수별로 식별한다.
- 자동 진행과 조기 호출에서 보상 지급, 카드 선택 대기, 저장·복원, 수동 정지 유지가 중복되거나 누락될 위험을 점검한다.
- 기존 검사가 보장하는 범위와 새로 필요한 검사를 구분한다. 수치나 밸런스 결론은 동일 조건 실험과 사람 플레이를 별도로 확인한다.

## 인계 형식

각자 완료 시 다음을 짧게 남긴다: 기준·결과 커밋, 수정 파일과 목적, 실행한 검사와 결과, 확인하지 못한 항목, 상대방에게 필요한 다음 행동. 완료 전인 기능과 실제로 배포된 결과를 명확히 구분한다. 사용자가 요청한 커밋·푸시는 작업과 검증 후 수행하고, 실패하면 상태와 이유를 알린다.
