# r36 — 이야기·빙결 표시 마무리

## 반영한 수정

- 이야기 그리기를 `DrawInterface`의 마지막으로 통일했다. 일반 실행과 성능 계측이 같은 그리기 경로를 사용하고, 말풍선까지 그린 뒤 경고 영역을 검사한다. 기존 방식은 성능 계측 중 이야기 그리기가 빠졌고 말풍선도 경고 검사에서 제외됐다.
- 적 말풍선의 테두리·아래 꼬리까지 영역을 예약한다. 낮은 창에서 지도 내부만으로는 자리가 부족하므로 이야기 말풍선은 HUD와 조작부 사이의 화면 여백도 사용한다. 경고·웨이브·대장 이름표와 겹치지 않는다.
- 이야기 대사를 끄면 아직 방문하지 않은 전장에서도 자동 대화창이 열리지 않는다. 끈 동안의 승패·웨이브 상태를 추적해 다시 켰을 때 지난 승패·웨이브·성채 피해 대사가 뒤늦게 나오지 않게 했다. 준비 중 명시적인 오프닝 다시 보기는 계속 가능하다.
- 그르낙은 `EnemyBoss.png` 대기 프레임의 실제 인물 영역 `(48,44,88,96)`을 사용하고 가로세로 비율을 유지한다.
- 빙결 M 수치·피해·저장 형식은 그대로다. 둔화 색, 취약 피해 숫자, 반경70 서리 원, 첫 배치 세린 대사를 실제 렌더 경로에서 확인했다. Core는 `f75b46d` 대비 diff 0이다.
- 검사 전용 코드는 개발판·명시적 인자·격리 제품으로 제한했다. 일반 QA에서는 이야기를 계속 끄고 성능 검사에서만 `-Story`로 켤 수 있다.

## Web 실제 입력 검사

Edge headless WebGL, CSS/캔버스 1280×720·844×390·390×844. `Tests/StoryWeb.cjs` 42개와 실제 Esc→메뉴→이야기 설정 진입 3개, 합계45개 통과했다.

- 오프닝을 Space로 끝내 첫 전장 소개로 진행, Esc로 건너뛰기.
- 첫 소개를 마친 뒤 같은 프로필에서 페이지를 새로 열어 네 전장 소개가 다시 열리지 않는지 확인. `fx-smoke=remember` 경로에서 실제 PlayerPrefs/IndexedDB를 사용한다.
- 실제 설정 버튼으로 대사 끄기·저장, 새로운 전장의 미방문 플래그를 검사에서 준비해 자동 대화창이 열리지 않음 확인, 끈 상태에서도 명시적 오프닝 다시 보기 확인.
- 대장 등장·함성, 성채 피해, 적 말풍선, 승리 한 줄과 습지 엔딩, 패배 한 줄.
- 빙결 첫 소개, 둔화 색·취약 숫자·서리 원 그리기와 대사 끄기, 기본 자동 검사에서 이야기 비활성.
- 세 화면 크기에서 경고 영역의 화면 내부 배치·비겹침, 대화 본문 높이, 그리기 전후 전투 직렬화 불변을 검사했다. 종료 상태는 저장용 전투 복사를 지원하지 않아 공개 Battle 직렬화를 비교하며, 준비/전투는 기존 저장 스냅샷을 비교한다.

전투 사건·승패는 명시적 개발 fixture가 주입한다. 빙결 화면은 색과 숫자를 분명히 확인하기 위한 합성 시각 효과를 사용한다. 이 화면 검사를 자연 경제 승리나 사람 재미 증거로 취급하지 않는다. 원본 로그·화면은 `r36-story-evidence-20261112/`에 있다.

기존 Web 검사도 재실행했다: `WarningsWeb.cjs` 40개, `SlotMenuWeb.cjs` 31개 모두 통과. 기존43종 `Run-*Checks.ps1`도 전부 통과했고 구 규칙216판 해시는 유지했다. 잠긴 기존 LossEnemySummary 실행 파일 대신 별도 출력 이름을 사용했다.

## Windows 확인

- `ComparisonBuild.R36LocalValidation`로 로컬 Windows 후보·일반 릴리스·격리 스토리·성능 검사판을 같은 소스에서 빌드했다. 후보 실행은 `Tests/bin/TacticalCandidate/Playtest.cmd`다. 공개 웹/다운로드는 교체하지 않았다.
- 별도 제품 `EmberBastionStoryReview`, `--tactical-playtest --story-review`: 실제 표시 창에서 오프닝 Repaint 확인→첫 전장 소개→PlayerPrefs 저장→표시용 seen 메모리를 비우고 실제 PlayerPrefs 재조회→같은 전장 재방문 시 소개 생략을 확인했다. 자동 종료했고 해당 제품의 검사 저장은 지웠다.
- Windows의 대화 진행은 검사기가 실제 View의 진행 메서드를 호출한다. 키보드·포인터 입력은 위 Web에서 검증했다. Windows PlayerPrefs 재조회는 동일 프로세스이며, 프로세스를 다시 시작한 영속성 검사로 주장하지 않는다. Web은 실제 페이지 재시작으로 영속성을 확인했다.
- 기본 `PerformanceQA` 숨김 실행의 `story-enabled.txt=False`: 일반 QA에서 이야기 비활성, 저장/복원·재생·체크포인트 검증 통과. 최초 제한 권한 실행의 레지스트리 저장 실패 뒤 격리 QA 저장 권한으로 재실행해 통과했다. 숨김 실행을 FPS 자료로 사용하지 않는다.

## 적80~99명 실제 표시 성능

브라우저와 빌드를 종료하고 Windows D3D11 표시 창에서 `Run-NativePerformance.ps1 -Visible -Story`를 실행했다. 자연 경제 스냅샷의 적80~99명, 실제 빙결 효과와 계속 표시되는 아군·적 말풍선을 함께 그렸다. 해당 검사판은 말풍선 두 개를 유지하는 부담 조건을 만들지만 전투 상태를 바꾸지 않는다.

| 화면·상태 | 유효 프레임 | p95 프레임 시간 | 16.67ms 예산 |
|---|---:|---:|---|
| 1280×720 · 선택 없음 | 900 | 2.588ms | PASS |
| 1280×720 · 병력 선택 | 900 | 2.593ms | PASS |
| 1920×1080 · 선택 없음 | 900 | 2.362ms | PASS |
| 1920×1080 · 병력 선택 | 900 | 2.528ms | PASS |

- 3,600개 프레임 모두 표시 창·GUI·유효 GPU 조건을 통과했다. 9800X3D·RTX5080, 개발판, uncapped/vsync0의 짧은 구간이다. 모니터 표시 FPS·저사양·장시간 결과로 일반화하지 않는다.
- 렌더 훅 합계: 둔화색96,488, 서리 원2,252, 아군 대사7,618, 적 말풍선7,600. 이는 워밍업·입력 검사 등을 포함한 그리기 호출 횟수이며 고유 적/프레임 수가 아니다.
- 고밀도에서 취약 피해 숫자0회는 기존 적35명 이상 숫자 생략 정책에 따른다. 숫자 색은 별도 저밀도 Web 화면에서 확인했다.
- 합성 입력30/30 유효. 전송→P 수신 p95 0.456ms, 전송→처리 프레임 끝 p95 3.338ms. 실제 키보드·디스플레이 지연을 포함하지 않는다.
- 실제 격리 저장/복원·재생·정지 복원·체크포인트/손상 거부도 통과했다. 원본과 분석은 증거 폴더의 `native-visible/` 및 `r36-performance-analysis.log`에 있다. 원본 이름은 UTC11일이며 한국 날짜는12일이다.

## 재현

```powershell
node Tests/StoryWeb.cjs
$env:STORY_MENU='1'; node Tests/StoryWeb.cjs
Remove-Item Env:STORY_MENU
# Unity 빌드 진입점: EmberBastion.Editor.ComparisonBuild.R36LocalValidation
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-NativePerformance.ps1 -Visible -Story
python -X utf8 Tests/Analyze-NativePerformance.py <생성된 PerformanceEvidence 폴더>
```

실패를 덮어 통과시키지 않았다. 최초 엔딩 fixture의 검사기가 종료 전투를 복사하려다 멈춘 문제와 낮은 창의 말풍선 공간 부족을 고친 뒤 다시 검사했다. 재생·저장 검사와 사람 평가를 구분한다.

## 인계

r34 이야기 마무리와 r36의 표시·성능·첫 빙결 소개 검증을 완료했다. 대사 내용은 Claude 초안 그대로다. 플레이 관찰표에는 빙결 선택 이유와 이야기 방해/도움 질문을 유지하고, 제거한 잔불 소리와 이미 끝난 규칙4 활성화 시점에 관한 낡은 문구를 정리했다.

남은 것은 사람10분 플레이·실제 휴대폰·저사양 검증과 이번 수정의 새 Claude 독립 검수다. 대장장이·빙결 수치, Q안, 새 병과/전장, 영구 성장, 공개 배포는 진행하지 않았다.
