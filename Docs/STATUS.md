PC와 모의 Android 화면에서 실제 Web 캔버스의 1번 자리 클릭/탭으로 200→135G 배치, 시작 버튼으로 1웨이브 전투 진입을 스크린샷으로 확인했다. `web-smoke/report.json`의 로딩 시간은 이 PC의 로컬 HTTP/소프트웨어 렌더 측정으로 실서비스나 물리기기 성능이 아니다.
- PC와 모의 모바일 Web 스크린샷에서 화면 크기·라벨·터치 좌표를 확인했지만 실제 스마트폰, OS 화면 전환, 접근성 도구, 수동 한 판의 재미와 밸런스는 미검증이다. 세로 화면에는 다음 웨이브와 선택 정보 패널을 추가했으며 가로 플레이를 포함한 실기기 검수가 필요하다.
- 한국어 렌더링을 위해 나눔고딕과 SIL OFL 원문을 포함했다. Web 개발 빌드는 압축 해제 상태이며 로딩/전송량, 서비스 환경의 MIME·압축·캐싱·메모리 조건은 추후 측정한다. 웹 운영판에 배포하거나 기존 저장을 읽지 않았다.

이 섹션은 아래 초기 상태 기록보다 우선한다. Web 최초 실패와 C# 최초 테스트 실패는 성공으로 집계하지 않는다.

## 서리 병과 및 창 모드 확인 추가

서리 투사체를 단순 사각형에서 밝은 눈송이 형태로 바꾸고 Windows·Web 개발 빌드를 다시 만들었다. 모의 PC 전투 시작을 확인했고 연속 캡처 `web-smoke/frost-frame-10.png`에서 발사체가 적에게 향하는 모습을 확인했다. 실제 기기와 사람의 수동 검수는 남았다. 제한 환경의 첫 빌드는 라이선스 초기화에서 중단했고 해당 테스트 프로세스만 종료한 뒤 라이선스 접근이 가능한 방식으로 다시 빌드했다.

서리 병과를 추가했다. 90G 배치, 50G 2레벨, 90G 분기, 목표 우선순위와 준비 저장을 지원한다. 기본 공격은 적을 둔화하고, 혹한 분기는 둔화를 강화하며 빙결 분기는 다섯 번째 공격으로 적을 잠시 멈춘다. 표시에는 Free Pack 수도사 그림을 임시 사용한다.

독립 규칙 검사 84개가 통과했다. `Tests/Compare-Frost.mjs`는 기본·혹한·빙결 편성을 열 개 웨이브의 총 360개 시점에서 체력, 이동, 둔화와 빙결 등을 기존 웹 규칙과 대조했고 차이는 0이었다. 기존 전장과 병과 비교도 차이 0이다. 이 비교는 테스트 편성에서의 규칙 확인이며 전체 게임 동등성이나 밸런스 검증은 아니다.

개발용 Web 테스트에서 서리 배치, 목표 변경, 준비 저장과 복원, 작은 화면의 3레벨 분기 선택을 확인했다. 이후 PC 세 전장과 모의 모바일 세 화면의 빠른 실행에서 브라우저 오류가 없었으며, PC 숲길 궁수의 목표 변경과 저장 복원 화면도 확인했다. 이미지는 `web-smoke/frost-mobile-restored.png`, `web-smoke/frost-branch-fixture-a.png` 등에 남겼다. 분기 화면은 시험용 상태다. 초기 200G에서 자동 클릭으로 1웨이브를 마치고 판매 후 궁수를 3레벨 저격 분기로 올려 저장·복원한 화면도 확인했다 (`desktop-branch-restored.png`). 이는 자동 입력 결과이며 실제 휴대폰과 사람의 수동 플레이는 아직 검증하지 않았다.

Windows 플레이어의 격리 실행에서 창 모드 → 전체 화면 → 창 모드 전환을 확인했고 결과는 `window-smoke.txt`에 기록했다. 이는 전환 함수 확인이며 실제 F11 키나 화면 버튼의 수동 입력 확인은 아니다. 너무 작은 창은 안내를 표시하고 게임 시간을 일시 정지한다.

## 설치 후 진행 추가

사용자가 설치 완료를 알려 계속 진행하도록 요청했다. Unity6000.6.7f1(b22767f04f04), WebGLSupport/WindowsStandaloneSupport 실파일을 확인했다. 첫 제한 실행은 AppData 캐시 접근 거부/라이선스 초기화 대기로 멈췄고 이 프로젝트의 해당 PID만 종료했다. 승인된 권한 재실행에서 Unity Personal entitlement 확인과 라이선스 갱신에 성공했다. 인증 정보는 프로젝트에 복사하지 않았다.

실제 Package Manager에서 없는 `com.unity.modules.inputlegacy`를 발견해 제거했다. InputLegacy DLL은 Editor에 내장되어 있어 별도 패키지가 필요하지 않았다. 이후 Unity C# 스크립트 컴파일 성공과 `Assets/Scenes/Comparison.unity` 생성을 확인했다. 현재 Windows 플레이어 빌드와 실제 실행, Web 빌드는 계속 검증 중이다. 아래 초기 환경 기록보다 이 추가 기록을 우선한다.

## 아직 남은 확인

1. Unity6000.6.7f1에서 실제 컴파일 오류를 해결하고 `Create comparison scene` 실행. Editor에서 200G 배치→시작→잔불→승패/재도전 한 판의 실제 입력과 화면을 기록한다.

4. Web 모듈 설치 후 빌드. 압축 비활성 개발 빌드를 로컬HTTP에서 실행해 로딩 크기/시간/메모리/입력/오류를 기록한다. 이후 적절한 압축·캐싱을 정한다. WASM MIME/application 지원, WebGL2/WebAssembly 환경, 실제 Android Chrome/iOS Safari에서 앱이탈·회전·터치 좌표와 메모리 한계를 확인한다.

## 기능 경계와 후속 기획

첫 판은 전체 게임의 첫 비교 납품이다. 3레벨 분기·타깃 우선순위 변경·서리/기술자·조기호출·성장·캠페인 이동·무한모드는 이번 구현에서 제외했다. 따라서 웹판과 완전 동등하지 않다. 저장은 구현하지 않았고 메모리 전투만 유지한다. 다음 저장 경로는 comparison 전용 폴더/버전키로 고정하며 웹 저장을 이관하지 않는다.

다음 순서: 첫판 조작/가독성 검수 → 맵2 굽이·양문 전략 → 병과 분기와 준비 편성 저장 → 캠페인 성장 → 장기 무한 도전과 기록. 60종을 한 번에 이식하거나 없는 동작을 새 원화로 만드는 범위는 포함하지 않는다.
