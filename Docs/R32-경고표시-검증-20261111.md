# r32 2·3-1 — 위기 추천·출현 예고 검증

## 변경

- 추천 병력을 강화한 뒤에도 같은 자리를 계속 추천하던 문제를 수정했다. 배치·강화·판매로 제안이 무효가 되면 배너와 추천 고리를 함께 지운다. 전술 카드 선택 중에는 두 경고를 숨긴다.
- HUD·하단 조작부·웨이브 배너·대장/선택한 적 이름표의 실제 화면 영역을 먼저 예약하고 경고 문구를 빈 영역에 배치한다. 긴 출현 문구는 줄바꿈한다. 성문 고리는 원래 성문 위치를 유지한다.
- 같은 성문이라도 출현 시각이 다르면 별도 예고다. 종류와 수는 같은 시각인 그룹만 합친다. 다음 웨이브는 현재 그룹의 마지막 적 출현과 웨이브 간격 중 늦은 시각을 기준으로 계산한다. 이전 방식의 잘못 합쳐진 숫자·조기 카운트다운을 회귀 검사로 막았다.
- 전투 규칙·가격·웨이브·저장 형식은 바꾸지 않았다. `cb24a2b` 이후 Core diff가 없다.

`Tests/WarningsWeb.cjs`, Edge headless WebGL, CSS/캔버스 화면 크기 1280×720·844×390·390×844. 원본은 `r32-warning-evidence-20261111/`에 보관한다.

- 위기 19개: 빈 자리 배치, 전 자리 사용 중 강화, 돈 부족, 성채 피해, 대장 이름표와 웨이브 배너, 기존 danger 요청, 웨이브당 2회 제한과 다음 웨이브 초기화.
- 출현 21개: 준비, 다음 웨이브, 웨이브 중간 지연 그룹, 고개/습지의 양쪽 성문 동시 예고, 전술 창에서 숨김, 빠른 호출의 확인 입력 두 번 후 다음 웨이브 재개.
- 모든 화면에서 예약한 사각형끼리 비겹침·화면 안 배치와 표시 전후 전투 직렬화 동일성을 검사했다. 1280·844는 52px 웨이브 배너, 390은 실제 축약형 36px를 확인했다.

- Windows 후보 개발판, 일반 Windows 릴리스, Web 검사 빌드 성공. 후보 실행: `Tests/bin/TacticalCandidate/Playtest.cmd`. 공개 다운로드와 기존 웹 배포판은 교체하지 않았다.

## 검증 한계와 실패 기록

- 이 화면 검사는 `Debug.isDebugBuild`인 Web 전용 `crisis=1` / `spawn-case` fixture다. 적·체력·시각을 주입하고 시뮬레이션 속도를 0으로 고정한다. 자연 경제 전투·실기기 터치·사람의 재미·FPS 측정으로 부르지 않는다.
- 위기 sound 사례당 기존 danger 요청 1회, 실제 재생 로그 최대 1회다. 헤드리스 브라우저의 자동 재생 제한으로 실제 청취를 입증하지 않는다. 위기 전용 소리를 새로 중복 호출하지 않았다.
- 고개에 두 성문이 **정확히 같은 출현 시각**인 사례를 찾으려던 최초 fixture가 실패했다. 실제 그룹에서 두 성문 예고가 함께 보이는 4초 창을 찾아 검사하도록 고쳤다. 고개의 두 적 그룹이 동시에 출현한다고 주장하지 않는다.
- 최초 빠른 호출 검사는 확인 버튼을 한 번만 눌러 멈췄다. 실제 0.3초 확인 지연 후 두 번째 입력을 넣었다. 게임의 확인 절차를 제거하지 않았다.
- 새로운 Claude 독립 검수는 아직 없다. 이 문서는 Codex 구현·검사 기록이다.
