# Terra 구현 인계 — 전술 선택과 병과 역할

작성: 2026-11-09, Astra / 조사 기준: `7b93188` / 상태: **T1/T2 코어 및 T3 개발 후보 구현·검사 완료, T4 미착수**

먼저 [게임 방향서](ASTRA-GAME-DIRECTION-2026-11-09.md)를 읽는다. 사용자 요청은 이번 턴에서 방향과 문서를 남기는 것이며, 이 문서 작성으로 게임 구현·플레이 검증이 완료된 것은 아니다. 이후 Terra가 작업을 시작할 때 `AGENTS.md`, 최신 `CLAUDE-DIRECTION.md`, `CLAUDE-REVIEW.md`, `STATUS.md`를 다시 확인한다. 다른 세션의 파일·미커밋 변경을 덮어쓰지 않는다.

현재 구현·검증 범위는 [STATUS 최신 기록](STATUS.md)과 [CODEX-HANDOFF](CODEX-HANDOFF.md)을 따른다. 일반 카드·리롤은 규칙4 개발 후보에 연결됐고 기본 실행은3이다. 아래 내용은 구현 계약이며 사람 평가·최종 배포 완료를 뜻하지 않는다.

## 1. 첫 완료 단위

**기존 그림으로 바위 고개 기본을 플레이하면서 세 번의 전술 선택, 유료 다시 뽑기, 선택 전후 저장·재개, 읽을 수 있는 효과 표시를 확인하는 Windows 후보.** 같은 기능을 네 전장·세 난도에서 사용할 수 있어야 한다.

이후 동일한 비공개 v4 후보에서 병과 상성·후반 압박을 분리 비교하고 통합한다. 선행 API만 있는 v4를 기본 새 전투로 켜지 않는다. 마지막 통합 단계 전까지 사용자 기본 생성은 규칙 3이다. 개발 후보는 격리 저장소/프로필만 사용하며 테스트 기록을 사용자 진행에 합치지 않는다.

### 가장 먼저 고칠 결합

현재 `Reinforcements != null`은 카드 상태의 존재와 증원 모드의 뜻을 동시에 가진다. 일반 카드 객체를 붙이기만 하면 증원 밀도 1.15가 붙고, 난도 변경이 잠기며, 일반 완료·보급·배지를 기록하지 않는다.

- 명시적 일반/증원 모드(예: `BattleMode`)를 두고 카드 상태와 분리한다. 이름은 기존 구조에 맞춰도 된다.
- v0~3 저장은 기존 `reinforcement` 존재 여부로 원래 모드를 복원한다. 새 필드의 기본값 때문에 구 증원 저장이 일반으로 바뀌면 안 된다.
- 카드 효과 조회는 드래프트로, 증원 추가 밀도·난도 제한·해금·기록은 모드로 판단한다.
- 신규 일반 카드도 일반 완료·배지·보급·다음 전장 경로를 탄다. 보급은 전역 첫 클리어 기준이며 규칙마다 중복 지급하지 않는다. 상한 60G 유지.
- 신규 증원도 처음에는 기존 3·6 선택/최대 2장/추가 15% 밀도/기존 카드 값과 상성 프로필을 유지한다. 리롤은 제공하지 않고 리롤 저장값은 0이다. 밀도·웨이브 구성은 v3 증원을 기준으로 유지하며 일반 v4 튜닝을 일괄 공유하지 않는다.
- 웨이브·상성·카드 효과·배지·기록에 넘기는 규칙과 모드를 한 곳에서 결정한다. 여러 파일에 `>=4`와 새 숫자를 흩뿌리기보다 작은 규칙 조회 함수를 사용한다. 대규모 엔진 재작성은 하지 않는다.

## 3. 일반 전술 선택의 규칙

### 시점과 입력

1. 기본·도전·극한 모두 실제 3·6·9웨이브 시작 직전에 제시한다. 현재 `Wave` 표현에서는 2·5·8 경계다.
2. 선택 대기 중 적 이동·공격·등장·게임시간·잔불 쿨다운을 정지한다. 배치·판매·강화·조기 호출·조준 확정 등 전장 입력도 차단한다.
3. 카드를 고르면 효과를 한 번 적용하고 해당 웨이브를 정확히 한 번 시작한다. 원래 수동 정지 중이거나 저장에서 복원했다면 정지는 유지한다.
4. 선택은 무료이며 시간 제한이 없다. Esc는 선택을 건너뛰지 않는다. 정상 종료·저장 후 이어갈 수 있어야 한다.
5. 자동 다음 웨이브·조기 호출은 기존 구조상 보상을 제시 전에 지급할 수 있다. 그 순서를 유지하되 대기·저장·재로드·재추첨 중 같은 보상을 다시 주거나 선택 후 누락시키지 않는다. 코어와 화면에서 각각 지급하는 방식은 금지한다.

### 카드 프로필: 7종 재사용

| ID/심볼 | v4 일반의 초기 효과 | 주의 |
| --- | --- | --- |
| 0 `ArcherHaste` | 궁수 공격 속도 ×1.2/장 | 간격 20% 감소와 다르다. 간격은 ÷1.2 |
| 1 `BombRadius` | 폭탄 폭발 반경 ×1.25/장 | 폭발 면적 +25%로 설명하지 않기 |
| 2 `SwordTargets` | 검사 동시 타격 수 +1/장 | Lv3 휩쓸기에도 같은 덧셈 |
| 3 `EmberCooldown` | 잔불 사용 시 설정할 재사용 시간 ×0.7/장 | 이미 흐르던 남은 쿨다운은 소급 단축하지 않음. 다음 사용부터 적용 |
| 4 `GoldIncome` | 기존 보상 ×1.15/장과 반올림 유지 | 즉시 골드 지급 카드가 아님. 리롤 비용·판매 환급에 적용하지 않기 |
| 5 `Range` | 궁수·폭탄병·서리 사거리 ×1.07/장 | 검사와 기술자 지원 범위는 제외. 미리보기·상세 수치 일치 |

위 수치는 첫 일반 카드 후보다. 효과를 변경할 경우 계산·설명·저장 프로필·검사를 같은 변경에 포함한다. 레벨 상한은 3, 투자·판매 공식은 기존 그대로다.

### 후보 풀과 중복

- 기존 보유 병과별 후보 규칙을 재사용한다. 공통은 잔불·골드·사거리, 검사/궁수/폭탄 전용은 해당 병력이 있을 때 제시한다.
- 공통 사거리 카드의 현재 적용 대상이 없으면 `현재 0명 · 이후 배치 병력에도 적용`을 명시한다. 가짜 적용 수나 “추천”을 표시하지 않는다.
- 한 제시의 카드 ID는 서로 달라야 한다. 한 전투에서 같은 효과를 재선택하는 것은 허용한다. 총 획득 수는 3장을 넘지 않는다.
- 기존 방식처럼 후보를 3개 미만으로 줄이지 않는 범위에서 보유 카드를 먼저 제외한다. 제외 순서는 카드 ID 순으로 고정한다. 따라서 제한된 편성에서는 중복 효과가 다시 나올 수 있다.
- 선택 대기 중 편성을 바꾸지 못하므로 제시·리롤의 후보 풀은 안정적이다. 저장을 다시 읽거나 창을 다시 그릴 때 후보를 재추첨하지 않는다.

## 4. 다시 뽑기 계약

- 비용: `60 + 30 × 이번 전투에서 이미 성공한 리롤 횟수`. 선택 창마다 60G로 초기화하지 않는다.
- 첫 후보는 선택 시점당 최대 2회, 전투 전체 최대 6회다. 횟수는 성공한 유료 변경만 센다. 이 제한은 무한 탐색을 막는 초기 설계값이다.
- 후보 풀에 다른 3장 조합이 없으면 비활성, `새 선택지 없음`을 표시한다. 정확히 3종뿐인 서리/기술자 중심 편성에서 순서만 바꿔 돈을 받지 않는다.
- 리롤 결과는 이전 세 장과 **집합 기준 최소 한 ID가 달라야** 한다. 공통 카드의 재등장은 허용한다. 카드 전용 난수만 사용한다.
- 무한 재추첨 루프로 다른 조합을 찾지 않는다. 후보 최대 7종이므로 가능한 3장 조합을 안정된 순서로 열거하고 현재 집합을 제외한 뒤 카드 난수로 고르는 방식이면 충분하다.
- 골드 차감·새 제시·난수 갱신·누적/현재 선택 리롤 수 증가를 하나의 성공 처리로 묶는다. 골드 부족·횟수 초과·창 없음·대체 조합 없음은 모든 값이 그대로다.
- 버튼 연타·IMGUI 재그리기·같은 입력 이벤트 재처리로 두 번 결제되지 않게 한다. 성공 후 입력 이벤트를 소비한다.
- 리롤 성공 직후 자동 저장한다. 저장 실패 시 성공한 화면 상태를 유지하고 실패 안내/재시도를 제공한다. 저장이 안 됐는데 저장 성공으로 표시하지 않는다.

## 5. 저장·체크포인트 계약

신규 저장에는 명시적 모드, 카드 프로필/선택 단계, 획득 카드, 현재 제시, 카드 RNG, 누적 리롤 수와 현재 선택 리롤 수가 재현 가능하게 들어가야 한다. 고정 일정에서 유도하는 값은 중복 저장하지 않아도 되지만 유도 규칙을 검사한다.

- 구 슬롯 키를 바꾸는 것만으로 호환을 해결하지 않는다. 기존 준비/수동 전투/자동 저장을 계속 찾고 원래 버전으로 읽는다.
- `RestorePreparation`·`CopyCombat`의 내부 생성은 명시 버전·모드로 초기화한다. 새 전투 생성자의 v4 기본 드래프트가 v0~3 복원에 남으면 안 된다. `CombatSave.ImportCombat`이 내부에서 만드는 임시 `PreparationData`에도 필요한 프로필을 전달하거나 공통 검증 경로를 분리한다.
- 신규 준비 저장은 카드 미선택·리롤 0. 실제 카드 창은 Fighting의 pending 상태다.
- 일반 v4의 완료 선택 수: 3 시작 전 0, 3~5에서 1, 6~8에서 2, 9 이후 3. 경계 pending 상태는 시작 직전 선택 수로 검증한다.
- v4 증원 및 v0~3은 기존 일정/최대 2 선택 검증을 유지한다. 전역 `MaxChoices=3` 변경으로 구 저장 검증까지 느슨하게 하지 않는다.
- 기존의 제시 대기 중 등장 대기열 비어 있음 등 상태 검증을 보존한다. 신규 필드 누락·범위 밖 모드·불법 카드 ID·중복 제시·음수/과다 리롤 수·일정과 맞지 않는 선택 수는 거부한다.
- `JsonUtility`의 누락된 숫자/불리언은 0/false와 구별되지 않을 수 있다. v4 프로필·모드에 `0=미지정` 식별자 또는 저장 스키마 표식을 두고, 필수 상태가 명시된 정상 저장만 받아들인다. v0~3에는 이 새 조건을 강요하지 않는다.
- 완료 선택 수를 `s`, 현재 선택 리롤 수를 `c`, 총 리롤 수를 `r`라 하면 `0<=c<=2`, `c<=r<=2*s+c`, `r<=6`을 검증한다. pending이 아니면 `c=0`이다. 선택 확정 때 `c`만 0으로 초기화하고 `r`은 유지한다. 구 규칙과 신규 증원은 `c=r=0`이다.
- 카드 창을 복원하면 같은 제시·가격·골드·획득 효과·다음 카드 RNG가 복원된다. 전투 RNG는 리롤로 달라지지 않는다.
- **선택 확정 뒤 시작한 웨이브의 체크포인트는 선택 후 상태**다. 해당 웨이브 재도전은 선택 카드와 이미 쓴 리롤 비용을 함께 유지한다.
- pending 상태와 이전 웨이브 체크포인트 사이에는 리롤 수·카드 RNG·골드 차이가 정상적으로 있을 수 있다. `CombatStore.ValidatePair`에서 무조건 같다고 요구하지 않는다. 대신 같은 전장·규칙·모드와 합법적인 선택 진행 관계를 검증한다.
- 과거 체크포인트를 복원하면 카드·골드·리롤·RNG도 그 시점으로 함께 돌아간다. 결제만 환급하고 새 카드를 남기는 혼합 상태를 금지한다.

## 6. 선택 화면과 피드백

필수 정보는 `전술 선택 1/3 · 선택 무료`, 다음 웨이브 구성 한 줄, 카드 이름·실제 변화·적용 병력 수, 보유 골드, `다시 뽑기 60G (남은 2회)`다. 선택 후 보유 효과를 다시 확인할 수 있게 한다. 새로운 팝업을 계속 겹치지 않는다.

- 기존 세로 카드 창은 높이 260/저장 실패 시 284다. 320×300에 리롤 줄만 추가하면 잘린다. 본문 스크롤과 고정 행동 영역 등으로 공간을 다시 나눈다.
- 320×300, 568×320, 800×500, 1280×720, 1920×1080에서 카드·가격·실패 재시도 버튼이 겹치거나 잘리지 않아야 한다. 글꼴을 계속 축소해 맞추지 않는다.
- 기존 중앙 `전투 이어하기` 버튼은 이미 있다. 저장 재개/선택 후 정지와 연결되는지만 회귀 확인한다.
- 손익 설명은 계산과 공유한다. 사거리 카드의 현재 대상 수, 공격 간격, 기술자 미적용, 기존 프로필의 +15%와 새 일반의 +8%가 서로 어긋나면 안 된다.
- 병과 역할 안내와 적 상세·예고는 실제 활성 규칙을 따른다. v3 기본 적에 v4 저항이 있다고 표시하지 않는다.
- 소리는 기존 효과음 경로를 재사용한다. 선택·리롤 소리만 크게 키우지 말고 Windows 실제 출력에서 공격·위험 경고와 함께 확인한다.

## 7. 상성·난도는 분리 비교 후 통합

v4 일반 후보에만 공통 상성을 넣는다. 첫 비교값은 질주 검사 피해 0.75, 방패 폭발 직격 0.75, 궁수 대질주·대방패 1.25다. 같은 적의 역할은 기본·도전·극한에서 동일하게 유지하고 난도 차이는 체력·등장 간격·구성으로 낸다. 적용 위치는 기존 도전과 같은 방어력 계산 전 계수다. 실제 최종 피해가 정확히 25% 바뀐다고 설명하지 않는다.

완화 후보는 기본·극한에는 상성을 추가하지만, 기존 도전의 저항과 궁수 보너스는 함께 약화한다. 난도별 결과를 따로 해석하고 합산 승률만으로 전체 개선을 선언하지 않는다.

다음 네 실험군의 편성·시드·보급 조건을 짝지어 비교한다.

| 후보 | 카드·리롤 | 상성 | 목적 |
| --- | --- | --- | --- |
| R3 | 현재 규칙 3 | 현재 난도별 조건 | 고정 기준 |
| C | v4 일반 | 현재 난도별 조건 | 카드만의 효과 |
| C+S | v4 일반 | 공통 0.75/0.75/1.25 | 첫 통합 후보 |
| C+S강 | v4 일반 | 공통 0.5/0.5/1.5 | 강한 상성의 부작용 비교 |

- 실제 현행 소스를 사용한다. 과거 고정 커밋 `bfcc0b7`을 치환하는 `Tests/r25-card-candidate.py`를 최종 구현 증거로 재사용하지 않는다.
- 기존 세 전장 4시드×9정책×잔불 유무×3난도, 습지는 별도로 같은 조건을 추가한다. 이후 편성 한 자리 교체, 조기 호출, 카드 선택 분기·리롤 0회/유료 정책을 필요한 범위에 집중한다.
- 한 자리 교체 실험은 총 투자금·자리·분기·타겟 정책도 기록한다. 가능한 한 비슷한 투자금에서 비교하고, 병과 가격 차이가 남으면 명시해 경제 차이를 순수한 병과 기여로 오인하지 않는다.
- 극한 숲길 후반 1.7→1.5는 별도 후보로 남기고 카드·상성 통합 후 평가한다. 기존 v3 값을 직접 바꾸지 않는다.
- 후반 밀도 조정은 어떤 웨이브의 어떤 적/성문 압박을 해결하는지 기록한다. 새 규칙의 적 구성을 바꿀 때 구 `Field.Waves`의 공유 객체를 수정해 v3까지 바뀌지 않도록 규칙별 데이터를 분리한다.
- 상성만으로 역할이 드러나지 않으면 배치·예고·타겟 정책·적 구성을 먼저 점검한다. 더 강한 저항을 자동 선택하지 않는다. 후보가 모두 나쁘면 상성 수치를 다시 설계하고 카드 묶음의 구현 진척은 보존한다.

## 9. 검사·증거의 최소 목록

기존 실행 명령은 저장소 루트에서 다음과 같다. 관련 단계에서 돌리고 최종 통합 때 회귀한다. 이번 문서 작업에서는 CoreChecks 277건만 실행했으며 아래 전체 목록의 통과를 뜻하지 않는다. 이 Windows의 기본 정책에서는 스크립트 실행이 차단돼, 검사 프로세스에만 `-ExecutionPolicy Bypass`를 지정했다. 시스템 정책은 변경하지 않는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-CoreChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-CombatSaveChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-CombatRetryChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-ReinforcementDraftChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-ReinforcementCombatChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-ReinforcementEffectsChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-ReinforcementPlaythroughChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-WaveVersionChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-ProgressVersionChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-FieldFourChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-R25ExtendedChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-R25LegacyCandidateChecks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File Tests/Run-RuleParityChecks.ps1
```

- 마지막 두 스크립트는 생성자의 `rng=seed;RulesVersion=3;FieldIndex=fieldIndex;`를 문자열 치환한다. 생성 경로 변경에 맞춰 검사도 수정하되 **기대 결과를 새 결과로 덮어 맞추지 않는다**. 기존 v1/v2 `9FD2B168AB217A4B15D24FDC0E120048F17D612AAF6FB2702EB4021E278A5A11` 기준과 v3 결과를 보존한다.
- 새 의미 있는 검사는 일반 카드의 모드 분리, 3·6·9 경계, 연타, 돈 부족·대체 조합 없음, 실패 시 상태 불변, 카드 RNG와 전투 RNG 분리, 제시/리롤/선택 직후 저장 재개, 체크포인트 비용·카드 일치, v4 일반 완료·배지·보급 및 구 기록 불변이다.
- 새 Web 빌드에서 `ReinforcementWeb.cjs`, `ReinforcementSaveFailureWeb.cjs`, `ReinforcementWarningLayoutWeb.cjs`, `ReinforcementEntryWeb.cjs`, `RulesRecordsWeb.cjs`, `CombatStoreWeb.cjs`, `AutoSaveWeb.cjs`, `PreparationSaveIsolationWeb.cjs`를 재사용하고 **일반 v4 3회·리롤 fixture를 추가**한다.
- 준비 화면에서 시간이 안 흐른 결과를 전투 정지 검사로 쓰지 않는다. 적이 실제로 움직이는 상태에서 카드·메뉴·재로드 전후 위치와 시간을 비교한다.
- 새 캡처·CSV는 `Tests/bin/` 하위 또는 새 이름으로 남긴다. 기존 `Docs/web-smoke` 증거를 덮어쓰지 않는다.
- 보고서에 커밋·규칙/모드·전장·난도·시드·보급, 게임시간과 실제시간/배속, 제시/선택/리롤·지출, 웨이브별 적 수/골드/구매·분기, 승패를 남긴다. 사용자 데이터 외부 전송은 추가하지 않는다.

## 10. 마지막 인계에 남길 것

`STATUS.md`와 `CODEX-HANDOFF.md`에 구현 완료 범위, 실제 실행한 검사, 후보와 최종 값 차이, 빌드 커밋·ZIP 경로, 미확인 Windows 소리/사용자 재미를 구분해 쓴다. Claude가 별도 세션에서 확인하기 전에는 독립 검수 완료로 쓰지 않는다. 문서 공유만으로 자동 전달됐다고 하지 않는다.

한 판 후 “여전히 고를 이유가 없다”면 카드/적 구성/효과 전달을 먼저 고친다. “후반에 살 것이 다 끝난다”가 확인되면 방향서의 제한된 정예 강화 후속 설계로 간다. 새 맵·새 그림 제작으로 작업 주제를 옮기지 않는다.
