## 잔불 제외와 호환 경계

사용자는 잔불의 재미 기여가 불명확하다고 판단해 ‘일단 빼고 로그라이트를 강화하는 방향을 기획에 남기자’고 지시했다. 앞서 요청한 잔불 버튼/강화 아이콘은 이 최신 지시에 따라 현재 화면에 남기지 않았다.

- 현재 UI에서 잔불 사용·강화 버튼과E/Space 진입을 제거했다. 정지 안내에 남아 있던 잔불 예약 문구도 없앴다.
- 후보 규칙4에서는 실제 `Ember`/`UpgradeEmber` 호출도 거부한다. 신규 전술 및 재추첨은 잔불 재사용 카드를 제외한다. 적용 병과가 없어 풀이2장뿐인 편성에서도3개를 제시할 수 있게 이후 병과에 적용될 비잔불 카드를 보충한다. 가능한 새 조합이 없으면 재추첨은 기존처럼 불가다.
- 제외 설정은 준비/전투 복원과CopyCombat에서도 규칙4에 맞게 유지한다. 저장 데이터의 카드ID/개수나 버전 번호를 바꾸지 않는다.
- 구 규칙0~3의 계산과 카드 풀은 보존한다. 이미 저장된 후보의 잔불 보유 효과를 임의로 다른 효과로 치환하거나 지출을 환불하지 않는다. 기존 후보의 진행 중 제시 카드에 잔불이 있었다면 그 항목은 화면에서 제외한다. 최신3개 선택지를 확인하려면 새 후보 판에서 시작한다.
- 이번 변경은 규칙4를 일반 실행의 기본값으로 전환하는T5가 아니다. 기존 다운로드/웹 배포/일반 실행판을 교체하지 않았다.

## 화살이 적 쪽에서 생겨 보이던 원인과 수정

두 문제가 있었다. 시뮬레이션이 한 프레임에 여러 틱 진행되면 새 화살이 처음 보일 때 이미 이동해 있다. 그리고 기존 `GUIUtility.RotateAroundPivot` 사용은 전장 확대/이동 행렬과 회전 중심의 좌표계를 섞어, 계산한 발사점과 실제 화면의 화살 위치를 어긋나게 했다.

렌더링 전용 추적기로 발사 직후 첫 그림을 활 끝에 붙이고 이후 진행 위치로 이어 준다. 같은 틱에 맞아 이미 사라진 화살도 활에서 발사하는 그림이 한 번은 보인다. 불러온 진행 중 화살은 발사점으로 되돌리지 않는다. 정지 중에는 새 시뮬레이션 갱신이 없어 첫 그림/진행 위치를 유지한다.

회전은 `전장 행렬 × 발사점 중심 회전` 순서로 합성해 화면에 투영한 중심이 움직이지 않도록 바꿨다. 단순히월드 좌표 로그만 확인하면 놓칠 수 있어, 실제GUI 행렬을 적용한 중심 전후 차이가0.01픽셀 이내인지도 검사했다. 수정 전/후 이미지와8개 원본JSON이 `arrows/`에 있다. [Unity GUIUtility 공개 참고 구현](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/IMGUI/GUIUtility.cs)의 행렬 처리도 참고했으며, 최종 판정은 이 프로젝트 실행판의 투영 검사와 실제 캡처로 확인했다.

투사체의 실제 위치·속도·명중·피해·RNG·저장 형식은 이 표시 수정으로 바꾸지 않았다. 발사 목적지/병과 정보는 저장되지 않는Cue에만 추가했다. 이번 잔불/전술 제외에 따른 후보 게임 변화와 화살의 표시 수정을 구분한다.

## 소리와 출력 장치

메뉴→소리/출력 장치에 음량 전환·테스트 소리를 넣었다. Windows 실행판의 ‘출력 장치 선택’은 **Windows 볼륨 믹서로 연결하는 방식**이다. 게임 내부에 별도의 장치 목록/라우팅 엔진을 만든 것은 아니다. 사용자가 앱 목록에서 이 게임의 출력 장치를 고른다. Windows 전체 기본 장치나 다른 앱 출력을 자동 변경하지 않는다.

연결 URI `ms-settings:apps-volume`은 [Microsoft 설정 실행 문서](https://learn.microsoft.com/windows/uwp/launch-resume/launch-settings-app), 앱별 출력 선택은 [Microsoft 지원 문서](https://support.microsoft.com/en-us/windows/hardware/audio/fix-app-audio-not-working-while-system-sounds-work-in-windows)를 확인했다. Web에서는Windows 버튼을 비활성화한다. Web 설정 화면/음량/테스트 버튼은 검사했으며, 사용자의 실제 장치 변경과 재청취는 이번 자동 검사에서 수행하지 않았다.
