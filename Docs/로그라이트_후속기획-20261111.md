# 로그라이트 후속 방향 — 병력과 전술의 조합을 중심으로

작성:2026-11-11. 사용자 최신 지시를 기존Astra/Terra 계획 위에 적용하는 후속 결정이다. **새 로그라이트 시스템은 아직 구현하지 않았다.** 현재 UI 정리와 후보 잔불 제외, 아래 향후 기획을 구분한다.

## 이번 결정

- 사용자는 잔불을 직접 누르고 강화하는 기능이 실제 재미에 기여하는지 의문을 제기했고, **일단 잔불을 빼고 로그라이트 쪽을 강화하자**고 지시했다. 기존 방향서의 ‘잔불 유지’는 현재 후보에 대해서는 이 결정으로 대체한다. 게임 이름 변경을 뜻하지 않는다.
- 하단 병력 카드·중복 강화/판매·상단 표적 선택을 없애고 지도 자리로 조작을 통일한다. 빈자리 클릭은 구매가 아니며 메뉴에서 병과를 고른다. 배치된 캐릭터를 누르면 좌우 강화/분기, 아래 판매, 해당 병과의 표적 선택이 나온다. 누른 채 끌어 놓는 선택도 지원한다.
- 메뉴는 상단과Esc. 출력 장치 선택은 소리 설정에만 둔다. 기기를 고르는 기능은 편의 기능이며 재미 시스템으로 가산하지 않는다.
- 현재 후보 규칙4의 신규 전술/재추첨에는 잔불 재사용 카드를 넣지 않는다. 스킬 사용/강화도 비활성화한다. 구 규칙0~3의 계산·저장 호환과 카드ID는 남긴다. 예전 후보에서 이미 보유한 잔불 카드는 다른 효과로 몰래 치환하지 않고, 진행 중 제시된 잔불 선택지는 UI에서 제외한다. 새 판에서 현재 선택 풀을 검증한다.

## 재미의 기준

‘더 많은 버튼’, ‘더 긴 웨이브’, ‘더 많은 수치 증가’는 목표가 아니다. 한 판 중간에 **선택 때문에 배치·강화·표적·골드 사용 계획이 바뀌고**, 다음 판에 다른 빌드를 시도할 이유가 생겨야 한다. 현재3/6/9웨이브의3회 전술 선택이 이런 효과를 주는지는 아직 사람 플레이로 입증하지 못했다.

첫10분에는 적의 위협을 보고 한 번이라도 선택을 바꿨는지, 왜 바꿨는지, 그 결과가 눈에 보였는지를 확인한다. 같은 편성으로 같은 버튼만 반복한다면 카드 개수를 늘려도 실패다.

## 다음 구현 후보 — 구현 전 소규모 실험

1. **병과별 빌드 정체성부터 한 묶음씩 만든다.** 검사 다중 타격/단일 압박, 궁수 연사/대장 대응처럼 이미 있는 분기를 출발점으로 삼는다. 단순 피해+8%뿐 아니라 공격 대상·행동·조건부 발동의 차이가 전투와 배치 판단에 나타나는지 비교한다. 새로운 효과 이름이나 수치를 지금 확정하지 않는다.
2. **전술 사이의 조합과 기회비용을 설계한다.** 예: 둔화·동결과 다른 병과의 후속 공격이 연결되는 빌드, 좁은 범위 화력과 넓은 범위 대응을 택하는 빌드. 전술이 모든 편성의 같은 정답으로 굳으면 대안과 제약부터 고친다. 상태 효과·공격 규칙 변경은 자동 판정/저장/성능 검사가 필요하다.
3. **선택지가 다음 구매를 유도하게 한다.** 현재 병력에 즉시 유리한 카드와, 다른 병과를 배치하면 열리는 카드의 장단점을 읽을 수 있게 한다. 카드에는 대상 아이콘·현재 적용 병력·현재→다음 수치를 표시한다. 적용 병력0명인 카드를 만능 이득처럼 말하지 않는다.
4. **위험을 감수할 보상을 검토한다.** 기존 조기 호출을 먼저 활용해, 더 어려운 전투를 받아들이는 보상이 실제 다음 강화로 연결되는지 본다. 선택형 적 강화나 이벤트는 기획 후보이며 아직 구현된 기능이 아니다.
5. **이번 판의 빌드를 기억할 수 있게 한다.** 선택한 전술과 주력 분기를 결과에서 확인하고, 다음 판에 바꿔 볼 선택을 제시한다. 화면에 상시 버튼을 늘리지 않는다.

## 첫 실험의 범위와 중단 기준

- 한 전장·기본 난도·같은 시드 묶음에서2~3가지 실제 빌드 경로를 비교한다. 한 번에 새 병과·새 맵·Lv4·유물·상점·영구 성장을 모두 넣지 않는다.
- 자동 검사는 승패·최대 적·소요 시간·미사용 골드·특정 빌드 독주·정체·저장 복원·프레임을 확인한다. 사람에게는 첫 위기 대응, 선택 이유, 효과 체감, 다음 판에 다르게 할 것을 묻는다.
- 사람이 차이를 설명하지 못하거나, 어떤 선택을 해도 같은 편성으로 끝나거나, 하나의 선택만 압도한다면 콘텐츠를 더 넣기 전에 해당 효과와 제시 시점을 고친다.
- 영구 공격력 상승으로 반복 플레이를 강제하는 구조는 우선하지 않는다. 먼저 한 판 안의 선택을 재미있게 만든다. 해금은 이후 수평적인 선택지 확대부터 검토한다.

## 작업 순서

이번 자리 중심 UI·화살 표시·설정을 완료하고 검증한다 → 현재 후보를 실제로 한 판 관찰한다 → 전술이 판단을 바꾸지 못한 지점을 기록한다 → 한 빌드 묶음만 상세 설계/실험한다 → 기준을 통과한 뒤 구현 범위를 넓힌다. 사용자 최신 지시 없는 임의의 난도 상향이나 신규 기능을 완료했다고 보고하지 않는다. 이번 문서 자체는 재미 개선의 증거가 아니다.
